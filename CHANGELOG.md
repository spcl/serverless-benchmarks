## WiP [1.3.0](https://github.com/spcl/serverless-benchmarks/compare/v1.2...v1.3) (XXX)

### Features

* Cold start enforcement for the local deployment: SeBS replaces the function container, and the local function servers report the first invocation of a container as cold. Requires the updated local run images.

* [RustFS](https://github.com/rustfs/rustfs) is the new default S3-compatible object storage for local and OpenWhisk deployments. Minio is deprecated and kept for reproducibility (`configs/storage-minio.json`). The self-hosted object storage implementation is now shared between backends.

* OpenWhisk: delete actions with `sebs resources cleanup --resource-type functions`.

* Reproducible Node.js dependencies: every Node.js benchmark and variant ships one `package-lock.json` per deployment, generated by `tools/lock_nodejs_benchmarks.py`, and build images install it with `npm ci`. Deployment packages are installed per benchmark module (`module_packages`), and builds fail if a lockfile is stale. The local run image locks its dependencies as well. Prebuilt platform binaries, such as the ones of sharp, are selected for the target architecture. Requires the updated build and run images.

* OpenWhisk: provider metrics include the platform's `waitTime` as `provider_times.waiting`: the time from receiving the request to provisioning a container.

### Bug Fixes

* `sebs docker build --platform` for another architecture (e.g., x64 images on an ARM machine) failed with Docker's containerd image store, the default since Docker 29: "image ... does not provide the specified platform". Docker's build API runs the legacy builder, so SeBS now builds such images with BuildKit (`docker build --platform`).

* Local functions failed to start when their server needed more than 2.5 seconds, e.g., Node.js containers emulated with QEMU; SeBS now waits up to 30 seconds.

* `sebs docker build` and `sebs docker push` exit with status 1 and list the failed images when an image fails; they always exited with 0.

* Node.js packages built for another architecture (e.g., arm64 functions on an x86 machine) contained native binaries of the build machine: npm selects platform-specific packages, such as sharp's `@img/sharp-linux-arm64`, by `--cpu`, `--os`, and `--libc`, not by `--arch`. The installer now passes all of them. Requires rebuilding the build images.

* Python packages for x64 functions built on ARM machines (e.g., Apple Silicon) contained ARM binaries: multi-platform build images run natively there, so the installer now downloads x86 wheels for x64 targets. Cross-architecture builds accept all manylinux wheels compatible with the build image's glibc instead of only `manylinux_2_17`, which rejected old pinned packages (e.g., Pillow 8.0.0) and new releases (e.g., numpy for Python 3.14). Python dependencies are always installed from wheels.

* Change to input of 120.uploader benchmark to conform with new Wikipedia policies (#308)

* Pull Minio images from the SeBS archive `spcleth/serverless-benchmarks:minio-reproducibility-archive-<release>`, as MinIO no longer publishes images on Docker Hub or quay.io.

* Fix restoring the cached configuration of self-hosted storage (Minio, ScyllaDB), and make the OpenWhisk `shutdownStorage` option work again.

* OpenWhisk: store the Docker image of newly created actions in the function cache, and download provider metrics of invocations through the library trigger, which did not record the activation ID.

### Improvements

* Local deployment on ARM machines (Apple Silicon, Graviton): the local build and run images for Python and Node.js are multi-platform (x64 and arm64), and SeBS warns when the configured architecture differs from the host's.

* PAPI hardware counters in local Python images use the distribution's PAPI through a small C binding with overflow sampling (`sebs_papi`). It replaces the pypapi submodule, whose bundled PAPI predates many current CPUs, and is compiled in the run images, which previously shipped pypapi without its native module. Requires the updated local run images.

* Support for multiple variants of the same programming language (#286).

* Support for new versions of Python and Java on AWS (#311).

* Self-hosted storage (Minio, ScyllaDB) advertises an externally reachable address to functions, detected automatically or set with `--external-address` when starting the storage. This removes the manual editing of storage addresses for OpenWhisk (#229).

### Deprecations

* Local deployment: Python 3.7 and 3.8, and Node.js 14 and 16 are no longer supported.

* Storage configuration files generated before 1.3 are no longer supported for OpenWhisk: they lack the `external_address` field, and functions would receive the Docker bridge address. Regenerate them with `sebs storage start`.

## [1.2.0](https://github.com/spcl/serverless-benchmarks/compare/v1.1...v1.2) (2026-03-16)

#### Container & Multi-Architecture Support

* Container deployment support for AWS Lambda (#205)
* Multi-architecture support (x86_64, arm64) for benchmarks (#227)

#### Language Support

* **C++ benchmarks**: Full support for C++ on AWS Lambda with dependency management system (#99, #251)
  - Docker-based build system with dependency caching
  - Dynamic dependency resolution with CMake generation
  - Support for Boost, OpenCV, igraph, PyTorch, hiredis libraries
  - C++ implementations: 010.sleep, 210.thumbnailer, 501.graph-pagerank, 503.graph-bfs, 411.image-recognition
* **Java benchmarks**: initial support for Java on all four platforms (#223), including benchmark **110.dynamic-html**.
* **Python**: Updated support for Python 3.8, 3.9, 3.10, 3.11, 3.12
* **Node.js**: Updated support for Node.js 14, 16, 18, 20

#### NoSQL Database Support

* Complete NoSQL storage integration across platforms (#214)
  - AWS: DynamoDB support with query interface
  - Azure: CosmosDB integration
  - GCP: Cloud Datastore support
  - Local/OpenWhisk: ScyllaDB for local testing
* New CRUD API benchmark (130.crud-api) demonstrating NoSQL operations (#214)
* Multi-tier storage system with both object and NoSQL storage

  - Datastore database management
  - Updated dependency versions for Python 3.10+
  - Custom deployment waiters
* **Local**:
  - ScyllaDB wrapper for NoSQL database 
  - Improved container lifecycle management
  - Memory measurement improvements
* **OpenWhisk**:
  - ScyllaDB wrapper for NoSQL database

## [1.1.0](https://github.com/spcl/serverless-benchmarks/compare/v1.0...v1.1) (2022-05-30)

### Features

* Support for the open-source FaaS platform OpenWhisk.
* New system of handling non-root containers that do not require rebuilding Docker images.
* Initial release of deploying functions as Docker containers, first released on OpenWhisk.
* Support for function states on AWS for correct deployment and configuration updates.

### Improvements

* Deprecate Python 3.6 on all platforms.
* Update documentation and tutorials.
* Docker build images for AWS now use official AWS images.
* AWS Lambda functions now support Python 3.9 and Node.js 14. Python 3.6 and Node.js 8 are no longer supported.
* Azure Functions support now Python 3.8 and Python 3.9, and Node.js 12 and 14. Python 3.6, Node.js 8, and 10 are no longer supported.
* Google Cloud Functions support now Node 12 and 14. Node 6 and 8 are no longer supported.
* OpenWhisk supports Python 3.7 and 3.9, Node.js 10 and 12.
